GazeAI CF2 Unit — Video In, Intelligence Out

Solution

Module-Based, Not Monolith

Same pattern as PatientData Unit evolution:

src/cf2/units/gazeai/
├── api/  campaign, ingestion, analytics
├── pipeline/  _entry, _runner, _stages
├── schemas/  campaign, camera, person, impression
├── tools/
│   ├── ingest/  scanner, probe, segmenter
│   ├── detection/  face_detector, quality
│   ├── tracking/  person_tracker
│   ├── reid/  embedding, dedup
│   ├── gaze/  head_pose, gaze, dwell
│   ├── demographics/  gender, confidence
│   ├── hitl/  queue, resolution
│   └── analytics/  reach, impressions
└── register.py

Pipeline = orchestration, Tools = capability, Schemas = contracts.

Client Provides Video

Initial scope per resposeRply.md — no camera/NVR hardware needed. 4–6 weeks for MVP.

  • Automated cloud upload (cellular gateway) + manual USB 3.0 SSD fallback
  • Multi-cam 270° rig: Activation Face + Left Flank + Rear Flank
  • 1080p 25-30FPS @ 2-10m, WDR, IR, vibration-dampened NVR

GPU Abstraction

config.py: BACKEND = local_gpu now → remote_gpu later. No hard-coded host GPU assumption per PRD 7.3. Standalone path: CF2 Unit → GazeAI Standalone product.

04/24

8-Stage Processing Pipeline

FR-02 to FR-05

1-3: Ingest → Detect → Track

Scanner + video_probe + segmenter → RetinaFace/YOLOv8-Face → ByteTrack. Extract 30 frames @1FPS from 33.42s.

4-5: Re-ID → Gaze

OSNet/BoT embedding + FAISS index for cross-camera dedup (Unique Reach). 6DRepNet head pose + L2CS-Net gaze + activation_zone + dwell threshold.

6-8: Demographics → HITL → Analytics

FairFace gender + confidence. <85% → HITL fast-tag queue. High conf → Analytics: reach, impressions, attention rate = impr/reach, avg dwell.

Why All 30 Frames Identical? — Baseline Heuristic

MVP Status

Reason

Unit running lightweight baseline fallback in src/cf2/units/gazeai/workflows/video_analysis.py. When full DL models (YOLO/MediaPipe/PaddleOCR) not enabled or weights missing, pipeline returns priors rather than crashing.

Artifacts: Heatmaps in .runtime/apps/39cf2d1024bb/gazeai/heatmaps/ — peak_xy [0.5,0.5], zones center weight 0.4.

How to Enable Real CV

  • Hook MediaPipe / OpenCV face mesh for real eye gaze + head pose per frame
  • Hook YOLOv8 / YOLO-World for real bboxes [x1,y1,x2,y2] pedestrians + billboards
  • Hook Tesseract / EasyOCR to read real text on 3D billboard

Impact: Real fluctuating metrics per frame, not static 0.40.

Deployment Topology — Edge vs Cloud vs Hybrid

Option A: Edge-Heavy

Onboard compute inside vehicle. Low latency, high hardware cost, power/heat issues.

Option B: Cloud Batch (Current)

Raw/compressed video uploaded to cloud GPU workers. Preferred for MVP — client provides video.

Option C: Hybrid

Edge detection/compression + cloud Re-ID/classification. Best for scale — PRD engineering decision.

Privacy & Compliance

Aggregate Only

Client portal: No raw video, no bbox crops, no admin settings. Only anonymized summaries per PRD 5.2. Support raw video deletion or automated face anonymization post-processing (NFR-02).

Smart City Note
